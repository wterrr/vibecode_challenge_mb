## II. Audit of reuse-first offline aligner options and copyright

- Reused original V3-19 `build_narrated_lesson`, eSpeak WAV, measured samples, `ResolvedTimeline`, H264/AAC FFmpeg `VideoAssembler`, V3-06 source-oracle frame renderer, V3-10/12 pixel/source QA, and V3-18 real developer FastAPI pipeline. No generic text-to-frame model added.
- Prior timeline fallback distributes text by character length; this is an **invented ratio**, not alignment, and is prohibited for V3-20 acceptance.
- Off-the-shelf offline forced-alignment/ASR models were not downloaded and their accuracy was not measured; claiming word-level alignment from such a model without a real pretrained checkpoint/ASR ground truth would be false. V3-20 instead avoids this uncertainty: it authors a **separate spoken utterance for each oracle-level semantic change** and measures its actual PCM sample count. The APPLY event begins at the next utterance's physically measured boundary; the first update frame is provably within one 12fps frame of that boundary. This is **utterance-start event synchronization**, NOT word-level or phoneme-level forced alignment or lexical transcript-as-heard confirmation.
- Official [eSpeak-NG repository](https://github.com/espeak-ng/espeak-ng) states GPL-3.0-or-later for the synthesizer, with other bundled license files. English voice/data rights and commercial derivative usage of generated WAV are **NOT independently cleared**. V3-20 is development-only; no release authority.

## III. Implementation and provenance

- New `learnflow_v3/event_alignment.py`: authoritative source-to-event compiler emits OBSERVE/ APPLY for each certified COMPARE step; INTRO/MECHANISM/RESULT/RECAP remain grounded separately. `visual_step` stays at original LOW/HIGH while the source comparison is spoken, then updates to the **next oracle state only at the APPLY utterance**. Each event preserves source trace hash, beat/segment IDs, claim/object identity, expected low/high/mid and exact text. The validator checks WAV PCM duration equality, proper scene/frame intervals, contiguous event ordering, SRT span, source IDs and same-source message; state `MEASURED_SEGMENTED_UTTERANCE_BOUNDARIES_NOT_WORD_FORCED_ALIGNMENT`, ASR/human outcomes UNMEASURED.
- Opt-in `event_aware=True` in original `learnflow_v3/narrated_lesson.py` keeps all V3-19 calls/outputs unchanged by default. Per-event source spec feeds the original V3-06 frame renderer with explicit previous-or-next oracle state; stage label shows READ MIDPOINT vs ADVANCE LOW/REDUCE HIGH/RECORD CANDIDATE. Original real eSpeak WAV, one SRT cue per spoken utterance, FFmpeg scenes and decoded full-frame and AAC QA remain. Final typed receipt adds immutable event policy/hash and links a fourth `event_proof.json` artifact only after media QA passes. `verify_narrated_lesson()` requires rederived proof and original pixels, refuses forged/rehashed event proof or missing speech/video.
- App `LEARNFLOW_V3_EVENT_ALIGNMENT` defaults OFF; requires prior `LEARNFLOW_V3_BINARY_PREVIEW` and `LEARNFLOW_V3_NARRATED_LESSON` ON and localhost/development. New `POST /api/v3/offline/binary-search-event-aligned` uses the SAME `app.state.pipeline`, original JobRunner stays V2 and feature OFF gives 404. Production flag ON fails startup, all nonbinary families return 422 ABSTAIN, no `CONCEPT_CARD` substitution, no public video URL, no job marked SUCCEEDED.
- `tests/v3/test_event_alignment_quality.py` checks real source-specific HTTP audio/video, per-source-step OBSERVE-before-APPLY, physical PCM counts/scene timing, manipulated audio sample count, subtitle offset, tampered/rehashed event proof, forged forced word alignment, changed source/trace, missing proof, unsupported family, flag OFF, remote peer, production startup, partial-write rollback.
