# V3-98 — Private production, one administrator, paid model, PostgreSQL

**Security model:** Only the bootstrap `admin` account exists. No registration, public reset or invite APIs. Password is salted PBKDF2-SHA256 (600k) in PostgreSQL. Sessions are stored as SHA256 token fingerprints in PostgreSQL; browser cookie is HttpOnly, Secure in production, SameSite=Lax. Each mutating request validates same-origin and a session-bound CSRF token. Failed logins lock the account for 15 minutes after five attempts. Logout revokes the session. `POST /api/jobs` has an atomic daily job limit (default 10); **this is not a financial ceiling**.

**Production fail-closed:** `ENVIRONMENT=production`, `LEARNFLOW_PIPELINE_MODE=real`, a real `DATABASE_URL=postgresql://...`, `AUTH_ENABLED=true`, `PUBLIC_ORIGIN=https://...`, `ADMIN_PASSWORD` (16+ characters), stable `AUTH_SECRET_KEY` (32+ characters), and either the paid `OPENROUTER_API_KEY` with `PLANNER_PROVIDER=openrouter` or `GEMINI_API_KEY` with `PLANNER_PROVIDER=gemini` are all required at startup. Production can never use the SQLite fallback or demo/fake pipeline.

The admin account is created **automatically at first boot** in the real PostgreSQL database; later boots never silently change its password. Set `ADMIN_USERNAME=admin`, supply a unique password through your secret manager, and store it privately. **No usable default password is ever committed or printed**. Password rotation is a separate authorized DB operation.

For paid GPT, `PLANNER_PROVIDER=openrouter` and `OPENROUTER_PLANNER_MODEL=openai/gpt-6-luna` feed the original strict Pydantic LessonPlan into the existing V2 video system: **not generalized V3 creative Manim, and not proof of 3Blue1Brown pedagogical parity**. Each provider POST uses strict JSON, hard output-token bound, no free fallback, no retry on uncertain billing. Existing planning validation may make one separate repair request per job. Confirm the exact model slug and pricing/account credit before deployment. `LEARNFLOW_DAILY_PAID_JOB_LIMIT` or `DAILY_PAID_JOB_LIMIT` is a count guard, not a provider-enforced USD budget.

Backend serves the compiled React landing at `/` automatically when production. `/login` is the only public HTML entry point. All APIs, the job library, source artifacts, and MP4 routes require an admin session. Production session-cookie `Secure` assumes HTTPS termination at your reverse proxy; set `PUBLIC_ORIGIN` to the user-visible HTTPS origin. No open CORS.

**Operations:** Use `docker compose --env-file .env.production -f compose.production.yml up --build -d` after filling the environment secrets. Mount the `artifacts` named volume persistently and back up Postgres; never run with multiple app replicas until job-queue ownership and artifact volume sharing are designed. Verify DNS, TLS, DB storage, paid provider balance, ffmpeg codec and a **user-authorized** end-to-end paid job before accepting production quality. This change does not make a paid request or provision a cloud database/deployment by itself.

**Acceptance levels:** source+CI PASS is distinct from a live paid-production PASS. Production deployment and paid API calls are deliberately NOT performed from CI without live operator secrets.
