# 1. PRODUCT CONTRACT

## 1.1 Product name

**LearnFlow AI — AI Learning Video Studio**

## 1.2 Core promise

Turn a learning question or topic into a short narrated educational video.

Examples:

```text
How does the TCP three-way handshake work?
Explain photosynthesis to a middle-school student.
RAM vs SSD for a beginner.
What causes inflation?
Explain recursion with a simple example.
```

The application is domain-general at the CONTENT PLANNING layer.

The renderer is deliberately constrained to a small set of GENERAL VISUAL PRIMITIVES.

This distinction is critical:

```text
arbitrary topic
    -> LLM lesson planning
    -> one of a small number of trusted visual specifications
    -> deterministic renderer
```

Do NOT create topic-specific code such as:

```python
if "tcp" in topic:
    ...
elif "photosynthesis" in topic:
    ...
```

## 1.3 MVP user inputs

Required:

```text
topic: str
```

Optional/defaulted:

```text
audience: Beginner
language: vi
target_duration_seconds: 90
visual_style: clean
```

Allowed duration options in UI:

```text
60
90
120
```

Allowed languages in MVP:

```text
vi
en
```

Allowed audience presets:

```text
Beginner
Student
Developer
Professional
```

## 1.4 Required demo topics

Before final submission, prove the system with at least these three domains:

```text
1. "How does the TCP three-way handshake work?"
2. "Explain photosynthesis to a middle-school student."
3. "RAM vs SSD for a beginner."
```

These examples are verification inputs, NOT hard-coded supported topics.

## 2.4 Why not copy Code2Video directly

Code2Video is a strong research reference because it separates educational planning, code generation,
and visual critique. However, its Coder stage synthesizes executable Manim code.

For this web application:

```text
LLM -> arbitrary executable animation code
```

is NOT in the MVP critical path because it increases:

```text
security risk
render failure risk
debugging complexity
host dependency risk
non-deterministic retries
```

We adopt the architectural idea:

```text
plan -> storyboard -> critique
```

but change implementation to:

```text
plan -> typed VisualSpec -> trusted renderer
```

## 2.5 Why MoneyPrinterTurbo is a useful reference

Adopt patterns, not its full architecture:

```text
provider abstraction
clear separation of LLM / voice / media services
TTS timing/subtitle metadata
FFmpeg-based final composition
provider-specific normalization at boundaries
```

## 2.6 Why VideoAgent is a future reference

VideoAgent is useful for a future `Source Mode`:

```text
PDF/document
-> parse/extract
-> grounded lesson planning
-> educational video
```

Source ingestion is DEFERRED for the VibeCode MVP.

# 7.2 GeminiPlanner

Environment:

```text
GEMINI_API_KEY=
GEMINI_PLANNER_MODEL=gemini-3.8-flash
```

Use the current Google GenAI SDK.

Important Gemini 3.8 rules for this project:

```text
use structured output / JSON schema
do not rely on markdown JSON extraction
validate Pydantic model again after SDK response
do not send deprecated sampling knobs unless docs explicitly require them
use a request timeout
```

Original implementation pattern to use:

```python
from google import genai

class GeminiLessonPlanner(LessonPlanner):
    def __init__(self, api_key: str, model: str):
        self.client = genai.Client(api_key=api_key)
        self.model = model

    async def create_plan(self, request: LearningRequest) -> LessonPlan:
        prompt = build_lesson_plan_prompt(request)

        def _call():
            interaction = self.client.interactions.create(
                model=self.model,
                input=prompt,
                response_format={
                    "type": "text",
                    "mime_type": "application/json",
                    "schema": LessonPlan.model_json_schema(),
                },
            )
            return interaction.output_text

        raw = await asyncio.to_thread(_call)
        return LessonPlan.model_validate_json(raw)
```

Do not copy this blindly if the installed SDK signature differs.
First run a tiny provider smoke test.

Provider error mapping:

```text
timeout                    -> planner_timeout        retryable=True
429 / quota                -> planner_rate_limited   retryable=True
401/403                    -> planner_auth_error      retryable=False
invalid structured output  -> planner_invalid_output retryable=True (repair path)
unexpected                 -> planner_provider_error  retryable=False
```

Never put `GEMINI_API_KEY` in logs.

# 8. LESSON PLANNING RULES

# 8.1 Planner system behavior

The prompt must tell the planner:

```text
You create concise educational lessons.
You are NOT writing animation code.
You output only the typed LessonPlan schema.
Use 3–6 scenes.
Every scene has narration and one supported visual intent.
Prefer simple explanations and progressive teaching.
Avoid unsupported visual types.
```

# 10. MEDIA TIMELINE

## 10.1 Audio-first invariant

For each scene:

```text
narration
-> TTS
-> ffprobe measured duration
-> render_duration = max(audio_duration + 0.30, 1.0)
-> pad audio to render_duration
-> timeline entry
```

Then and only then:

```text
render scene visuals using render_duration
```

Do NOT render visuals before the resolved duration exists.

## 10.2 Probe helper

```python
async def probe_duration(path: Path) -> float:
    ...
```

Execute `ffprobe` using `asyncio.to_thread` or `asyncio.create_subprocess_exec`.

Never use shell=True with user-derived path fragments.

Expected ffprobe concept:

```text
ffprobe -v error
-show_entries format=duration
-of default=noprint_wrappers=1:nokey=1
<path>
```

Parse finite float > 0.

## 10.3 Padding

Use FFmpeg to pad silence.

Concept:

```text
audio input
-> apad
-> trim to render duration
-> PCM WAV or AAC-normalized intermediate
```

Keep all scene audio on a consistent sample rate/channel layout before concat.

Target:

```text
48 kHz
stereo final output
```

Mono intermediate is acceptable if normalized by assembler.

## 10.4 Timeline persistence

After audio stage:

```text
artifacts/<job_id>/timeline.json
```

Write JSON atomically:

```text
timeline.tmp
-> os.replace
-> timeline.json
```

This is useful for debugging and future resume support.

MVP does not auto-resume interrupted jobs after process restart.

# 13. ASYNC JOB LIFECYCLE

## 13.1 Queue

Use:

```python
asyncio.Queue[str]
```

Single worker only.

Reason:

```text
FFmpeg/rendering is resource-heavy
single worker avoids accidental parallel CPU saturation
simple predictable demo behavior
```

## 13.2 Startup

FastAPI lifespan:

```text
create dependencies
start JobRunner
yield
stop JobRunner
```

## 13.3 Creation

`JobService.create_job`:

```text
normalize request
create UUID
persist QUEUED job
enqueue job_id
return persisted job
```

Important invariant:

```text
persist BEFORE enqueue
```

## 13.4 Worker behavior

```text
get job id
load persisted job
if missing: log and continue
if status != queued: log and continue

status=running
stage=planning
attempt_count += 1

await pipeline.process(job)

verify final artifact exists
persist artifact metadata
status=succeeded
stage=None
progress=100
```

Error mapping:

Known `PipelineExecutionError`:

```text
status=failed
stage=error.stage
persist structured error
```

Unexpected exception:

```text
status=failed
code=unexpected_pipeline_error
stage=current_stage or planning
retryable=false
message=sanitized exception type/message
```

Always call:

```python
queue.task_done()
```

inside `finally`.

## 13.5 No restart recovery in MVP

On application restart:

```text
old queued/running rows remain persisted
```

At startup, do NOT automatically re-enqueue them.

Optional UX:

Display:

```text
"Interrupted by application restart"
```

only if a later hardening checkpoint implements explicit reconciliation.

Do not add recovery unless requested.

```python
    conn = sqlite3.connect(db_path, timeout=10)
```

# 26. DEFINITION OF MVP DONE

The product is DONE only if all are true:

```text
A real user can open the deployed web app.
A user can enter a previously unseen learning topic.
A database job is created.
The HTTP request returns before generation completes.
The UI visibly tracks background stages.
Gemini returns a typed LessonPlan.
The plan is validated.
Narration is generated.
Audio duration is measured.
A timeline is resolved.
Trusted renderers create visuals.
FFmpeg creates a candidate video.
QualityGate validates the candidate.
The final artifact is atomically published.
The job becomes succeeded only after publication.
The user can watch the video.
The user can edit the display title/note.
The user can delete completed/failed jobs.
The UI works on mobile.
At least three different subject-domain demos work.
No topic-specific hard-coded implementation exists.
No local model/GPU is required.
No secrets are committed.
```

If any statement above is false, do not call the MVP complete.
